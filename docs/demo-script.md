# Demo script (5 minutes)

A walkthrough of CoreSpec for a supervisor, with the exact clicks. Each step has one line to say. Times are a guide; the whole run is about 5 minutes.

**The demo for the exam (early December 2026) is recorded**, not live: see "Recording" below. `tests/e2e/demo.spec.ts` follows the main run click for click, so a change that breaks a step fails a test.

## Before the demo (5 minutes earlier)

- Use **Chrome on a laptop**, window maximised (the builder needs at least 1024 px wide for the side-by-side layout).
- Open the live site once and wait for the 3D case to appear on the landing page and in the builder, then open the **Setup** tab once so the desk models load too. This warms the browser cache, so the demo doesn't wait on the 3D files.
- Start from a clean build: open `/builder`, click **New build** if the last one is still there.
- Have a **private window** ready to open (`Ctrl+Shift+N`) for the last step.
- Close other heavy tabs. The 3D view uses the graphics card.

## Optional: live chat (about 2 minutes, two devices)

Only where accounts are on (the **Phase 18 preview** and, once merged, production). Two devices side by side: a **phone as the user** and the **laptop as the admin**. It needs two logins and Supabase Realtime, so `tests/e2e/demo.spec.ts` doesn't run this part: walk it once by hand before the demo.

**Before:** on the phone, log in as a normal user. On the laptop, log in as an admin in a second browser (or a private window) and open **Admin → Chat** (`/admin/chat`). Both on the same wifi as the demo if you can. The laptop's inbox header should say **Live**.

Sending more than 5 messages in 30 seconds is refused on purpose ("You're sending messages too fast…").

## Recording

- Record the browser window only, at **1920×1080**, with the bookmarks bar hidden and the zoom at 100%. Chrome on the laptop, plugged in (the 3D view is smoother on mains power).
- Warm the cache as in "Before the demo", then start from a clean build.
- The desk view's default camera frames the setup at about three quarters of the view, on desktop and phone; press **R** before each desk-view shot so every take starts from the same framing.
- Record each segment (the main run, checkout, chat) as its own take; a fumbled click means redoing that take, not the whole video. Keep the cursor still while you talk over a step.
- For the chat segment, record the phone's screen with its own recorder and place it beside the laptop's in editing.
- Watch the first take back before recording the rest: check that the 3D view is sharp and the desk-view colours read as neutral greys, not purple.

## If the 3D view is slow to load

- **Nothing breaks without it.** The page first shows a technical drawing of the case, and every list, check, price and link works before (and without) the 3D view. Carry on talking and point at the summary; the 3D view fades in when it's ready.
- **Landing page:** the 3D case only loads once the page has settled. Scrolling down to the presets and back gives it time.
- **Still slow after ~10 seconds:** reload the page once. The second load comes from the cache (that's why to open everything before the demo).
- **3D view missing entirely** (old laptop, graphics drivers): the drawing stays. Say "on this machine the 3D view is turned off; here's what it looks like" and show `docs/screenshots/` (the builder, the exploded view, the setup tab and the desk view).
- **Camera in an odd spot after dragging:** click the 3D view and press **R** to reset it.

## If something else goes wrong

- **The build already has parts** from earlier testing: click **New build**, then load the preset from **Load preset → 1440p Sweet Spot**.
- **A step's item isn't in the picker:** type its name in the picker's search box (e.g. "MICKE", "S2000", "27GR93U").
- **A price looks off:** prices change; the "Checked" date says when it was looked at, and a check older than 14 days says "Price may have changed".
